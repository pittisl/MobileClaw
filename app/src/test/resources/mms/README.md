# MMS reference vectors

The two `.hex` fixtures were generated by the **unmodified AOSP composer**, not by
MobileClaw's encoder. Source: Android Messaging commit
[`de315b762312dd1a5d2bbd16e62ef2bd123f61e5`](https://android.googlesource.com/platform/packages/apps/Messaging/+/de315b762312dd1a5d2bbd16e62ef2bd123f61e5/src/com/android/messaging/mmslib/pdu/PduComposer.java).

`GenerateReference.java` records the reference inputs. `pixel.jpg` is a generated
2 × 2 solid-color JPEG, with no personal image data. The caption includes an emoji
to check UTF-8 octet lengths. Both cases use fictional NANP number +12025550198.

Regeneration requires that reference's PduComposer, GenericPdu,
MultimediaMessagePdu, PduBody, PduPart, PduHeaders, EncodedStringValue,
CharacterSets, SendReq, PduContentTypes, InvalidHeaderValueException and
MmsException. Compile the reference classes and generator on a JVM with trivial
Android adapters: Context returning ContentResolver, ContentResolver.openInputStream
throwing FileNotFoundException (the fixture always supplies byte arrays),
TextUtils.isEmpty, no-op Log, SparseArray backed by HashMap (get/put and
get-with-default), SimpleArrayMap backed by HashMap, and empty Uri.
Run `GenerateReference <this-directory>`. These adapters implement framework
containers only; no MMS encoding code is replaced or adapted.

The production encoder matches the entire reference output byte for byte,
including the WSP multipart lengths, SMIL/JPEG/text part headers, MIME tokens,
encoded recipient, and report settings. This proves wire serialization parity;
it is not a carrier delivery test. No test sends a message.

`aosp-size-boundaries.sha256` additionally covers 127, 128, 16383, 16384 and
262144-byte parts, using deterministic byte sequences rather than JPEG pixels.
This checks all three WSP uintvar widths used by real MMS payloads without
committing a quarter-megabyte golden PDU.
