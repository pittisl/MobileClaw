# Model services

Open **Settings > Model service**. Choose Gemini, OpenAI, Local server, or Custom;
enter a model ID available to that service; and save. Each service keeps its own
settings. Saving selects it for new chat turns, notification triage, follow-ups,
and daily memory consolidation. A running turn finishes using the configuration
it started with. There is no automatic fallback to another provider.

The Base URL is the API prefix, such as `https://api.openai.com/v1/` or
`https://generativelanguage.googleapis.com/v1beta/openai/`. Pasting a full
`/chat/completions` URL is also accepted. Changing the address clears the key field:
re-enter a credential intended for that address. Requests do not follow redirects.

**Test connection** sends only built-in synthetic prompts. It separately checks
streaming text, streamed tool-call arguments, structured JSON for notification
triage, and (when enabled) a small synthetic image. No actual device tools run and
no notification, memory, chat history or photo is included. A passing probe verifies
these small examples, not the model's reliability on arbitrary agent tasks.
Saving alone does not run the probe.

## A model already running on the phone

MobileClaw is a client of an existing OpenAI-compatible server. It does not bundle,
download or start an inference engine or its model weights.

1. Start the model server on the phone and bind it to loopback.
2. Select **Local server** and set its Base URL, for example
   `http://127.0.0.1:8080/v1/`. Enter the model name accepted by that server.
3. Select **No authentication** if the server does not require a credential.
   No `Authorization` header is then sent. If it requires one, select Bearer token.
4. Test the connection, then save. Enable image input only for a vision-capable
   server/model. Otherwise notification reasoning sends text only.

`localhost` refers to the Android device. For a server deliberately forwarded from
a development computer, use `adb -s SERIAL reverse tcp:8080 tcp:8080` and the same
loopback URL. An Android emulator can use `http://10.0.2.2:PORT/v1/` for its host.
Other HTTP addresses are rejected; use HTTPS for a LAN or remote server. HTTP
loopback is allowed for `localhost`, `127.0.0.1`, and `::1` only, plus the emulator
host alias above. A local service can run without an Internet connection; tools
that themselves depend on online services still need their own connectivity.

The local preset starts with a 300-second read timeout, an 8,000-token input budget,
and image input disabled. Adjust the budget to the actual model context, leaving
room for output. It covers the system prompt and **the entire tool catalog**, as
well as conversation text; 8,000 tokens may be too small for the full catalog.
The client reports an oversized turn instead of silently switching to a cloud
model. Budgets use the project's English-text estimate, not a tokenizer-specific
hard limit. Image tokens are not included in that text estimate.

## Credential storage and development builds

Profiles are stored as an atomic AES-256-GCM encrypted file in the app's
`noBackupFilesDir`; the encryption key is generated by AndroidKeyStore. Every write
uses a fresh IV. No API key goes into ordinary preferences, Activity saved state,
exports or backups. Clearing a service does not switch to another saved provider
or reload a developer default. Unreadable ciphertext or a missing Keystore key
leaves the app unconfigured until settings are re-entered or cleared. Root access
or instrumentation inside a running app can still access credentials in memory.

Ordinary debug builds and **all release builds** start without credentials or
private endpoint values. They can be configured in the app. For an internal debug
installation only, preserve the existing SDK settings in gitignored
`local.properties` and add:

```properties
LLM_DEV_DEFAULTS=true
LLM_API_KEY=your-own-development-key
LLM_ENDPOINT=https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
LLM_MODEL=gemini-2.5-flash
```

The seed is imported only on the installation's first initialization. Existing
runtime settings win. An internal APK built with this option still contains that
seed in its dex and must stay private. Updating an installation that already
initialized without a seed will not import it later; use the settings screen.

For a debug APK suitable for sharing, explicitly override local development
settings without editing the local file:

```bash
bash gradlew -Pmobileclaw.publicBuild=true :app:assembleDebug
```

`assembleRelease` always ignores development credentials, even without this flag.
The same guard strips the optional compile-time Notion token. Notion requires
its own API token, which cannot be entered through the model-service screen.
The distributed APK cannot use Notion because it contains no Notion token.
To try the implemented integration, follow the
[Notion build configuration](building.md#enable-notion-in-your-own-build)
to compile a debug APK with your own token and grant access to your pages.
